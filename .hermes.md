# DungeonMindBuddy Hermes Policy

DungeonBuddy owns campaign truth. Hermes owns conversation, planning intent, and tool orchestration.

## Authority

- Source artifacts are prose/evidence authority.
- The World Supergraph head is durable materialized campaign knowledge.
- Hermes sessions, chat history, summaries, and long-term memory are not campaign canon.
- Agents are not privileged writers.

## Graph-only factual retrieval

For campaign, setting, session, NPC, location, threat, encounter, continuity, or planning-fact questions:

1. Use DungeonBuddy World Graph read tools.
2. Search/resolve objects within the supplied world, campaign, focus, admissibility, and revision context.
3. Traverse bounded graph relationships when the question requires connected context.
4. Obtain source anchors through graph assertion support.
5. Read source text only through an anchor returned by graph retrieval.
6. Answer from admitted graph state and anchored evidence.
7. If evidence is partial or absent, preserve uncertainty and abstain.

## Forbidden product fallbacks

Do not use these as alternate factual discovery paths:

- Manifest lookup or manifest route indexes.
- Corpus indexes.
- Repository-wide Markdown search.
- Lexical/vector fallback outside graph admission.
- Arbitrary file-path reads.
- Ambient Hermes memory.
- Prior chat text treated as current campaign truth.

A graph miss is a coverage gap. Report it; do not hide it by searching another Markdown source.

## Target read-only tools

- `search_campaign_graph`
- `get_campaign_object`
- `get_object_neighborhood`
- `get_object_evidence`
- `read_source_anchor`

`read_source_anchor` accepts only an opaque source anchor returned by graph retrieval. User/model-supplied arbitrary paths are invalid.

## Conversation memory

- Reuse one Hermes session per Agent Interaction thread.
- Use prior turns to resolve intent, pronouns, and task continuity.
- Re-read current graph state for factual claims unless the user explicitly requests historical state.
- Do not store campaign facts, canon facts, session facts, NPC state, or worldbuilding details in Hermes long-term memory.
- Prefer Hermes memory off during the graph-retrieval spike.

## Answer policy

- Direct answer first.
- Cite graph-admitted source anchors for factual claims.
- Distinguish confirmed evidence, inference, missing evidence, contradiction, and graph coverage gap.
- Do not invent lore.
- Do not silently merge planning ideas into played/world canon.
- Do not imply a tool consumed context that it did not receive.

## Write policy

Until PR011 governed tools exist, Hermes is read-only for campaign authority.

Future writes must use typed DungeonBuddy tools and follow:

```text
preview_write -> proposal-bound and revision-bound GM confirmation -> confirm_commit
```

No autonomous graph or source mutation.

## Runtime boundary

- PR010B Rung 3 provides an embedded in-process Hermes `AIAgent` turn over the packaged `dungeonbuddy_graph` plugin.
- The default capability policy is graph-only / five-tool / read-only, but the runtime accepts a configurable policy (enabled toolsets/names, immutable graph scope, per-tool scope rules, allowed effects). Before the provider turn it discovers plugins under an isolated profile, resolves the model-visible tool surface, and fail-closes unless that surface matches the policy exactly. Hermes-wide `pre_tool_call` + thread tool whitelist enforce the same allowlist for every tool, not only graph plugin handlers. Graph handlers still inject authoritative scope at dispatch.
- This wrapper is **process-exclusive**, not a generally server-safe multi-tenant runtime: it temporarily prefers Hermes `agent.*` on `sys.path`/`sys.modules` and sets process-wide `HERMES_HOME` for the turn. A lock serializes these turns against each other only.
- Agent Interaction thread/session binding and durable conversation persistence remain later rungs.
- The eventual product path must use a real Hermes agent/session loop wired through that graph-only boundary.
- `hermes --oneshot` is not the product backend.
- A CLI smoke harness may remain only when clearly labeled development-only.
- Live/OpenAI synthesis is not a fallback when Hermes or graph retrieval fails.

## Local plugin setup

Embedded Rung 3 turns create an isolated process-local `HERMES_HOME`, force plugin discovery under that profile, verify the effective tool registry, then delete the temp home. Concurrent Rung-3 turns are serialized by an explicit runtime lock. They do not require mutating a user-global Hermes profile.

For transitional spike tooling that still uses the legacy plugin directory:

```bash
export HERMES_HOME="$PWD/.hermes-runtime"
export DUNGEONBUDDY_REPO="$PWD"
mkdir -p "$HERMES_HOME/plugins"
ln -sfn "$PWD/integrations/hermes/plugins/dungeonbuddy" "$HERMES_HOME/plugins/dungeonbuddy"
hermes plugins enable dungeonbuddy
hermes memory off
```

The existing transitional plugin still contains legacy manifest/corpus tools. They are implementation debt and are prohibited for PR010B graph-only dogfood. A later replacement rung removes them from the Hermes product toolset.
