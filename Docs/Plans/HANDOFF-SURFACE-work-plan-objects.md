## User experience and invariants

A generated typed plan appears in a distinct page object at the request’s captured location. The author edits step text/actions, checks selected steps, defers others, moves the object and presses one Save. The saved page contains a reference to that same retained plan. Reload restores its controls/state without a new model call or continuation. Checking is selection, not execution; only explicit Continue dispatches the existing exact reviewed step. Questions stay inline in conversation. Chat shows concise acknowledgment/activity and the normal cited reply, without another full plain-text result copy inside the old plan card.

The APP saved-work-plan owner already supplies review/CAS, source hash, step identities, selected/deferred state, stable dispatch identity, result projection and actual continuation admission. Reuse it. The current Markdown admission explicitly rejects GFM task-list items; rendering a Markdown checkbox does not create an interactive plan. The existing Surface proposal widget is temporary DOM outside editor JSON; it cannot serve as the saved object representation.

## Closed page representation

Introduce document-block fenced language dmb-work-plan-v1 containing exactly schema=dmb_surface_work_plan_ref_v1, world_id, document_id, conversation_id, source_turn_id, source_answer_sha256 and title. UUID/digest/nonblank title fields are validated; duplicate JSON keys, extra fields and nested/malformed fences are refused with recoverable source bytes. The canonical serializer produces a stable fence. A TipTap atomic block projects this reference with the shared interactive view. HTML import/paste cannot manufacture an admitted reference. A generated prose/media insertion is still inert and must reject a work-plan fence; only the typed plan-placement adapter may construct it from verified host identities. No provider is asked to output identities.

The reference stores no copied steps, execution state, provider prompt or new executor. Its identity is the World/document/conversation/source-turn/source-answer digest. Duplicate same-plan references within a page are refused at serialization/admission; copying it to a foreign World/document cannot read or execute that plan. Title/movement belong to the page; reviewed steps and results belong to existing APP work_plan. Removing/undoing the block removes only its page placement and never erases history, dispatches or other retained data.

Use a shared Surface object/host adapter. Build supplies its current editable page, conversation pointer, existing placement bridge and existing queued continuation dispatcher. Other surfaces render safely read-only until their owning action adapter is admitted; a shared component is not authority to execute Build operations on Plan/Play. No new runtime imports from DungeonOverMind.

A reference is a locator, not permission.

Current active conversation/page/edit admission controls editing and continuation; archived or foreign references remain inspectable with a specific obstacle and explicit original-conversation navigation. Do not silently reactivate a conversation. Late callbacks must not mutate another page or populate its composer.

Reuse saved plan CAS and local edit preservation. Existing dispatched step bytes remain immutable; edit by adding a new step under existing rules. Continue uses exactly the existing reviewed-step reference/dispatch and pending request owner, preserving newer composer text and honoring interrupted/uncertain request recovery. No event/ledger/provider receipt is invented, no automatic execution or new planner is added. Existing completed plans remain readable.

## Staging, placement and Save

Transfer the request’s real captured insertion basis from the existing pending Build request into a bounded plan-placement view/cache keyed by its actual turn identity. Do not infer a position from current focus after generation. After reload, restore only an exact unchanged basis; if unavailable/stale, preserve the generated object and require an explicit new page position with the existing picker/scrolling behavior. Historical plans can be explicitly placed using the current editable page. Never auto-replace a text selection with a work-plan object.

Before Save, the plan object is a reversible Surface placement with local edited rows and no page mutation. Its one Save first persists the reviewed plan via existing APP CAS, then inserts the host-constructed reference through the ordinary author editor transaction and page Save owner. Stable reviewed step IDs/cache survive retry. This is deliberately not a distributed transaction: if plan review succeeds but page Save fails, say review saved/page placement unresolved and retain both copies. Existing editor complete-copy conflict/recovery owns page uncertainty; the narrow local placement receipt defined below records this author transaction before mutation. It is not a BuildProposalRecord, provider reservation or server apply receipt. Do not create another insertion or redispatch generation on an unknown outcome. Re-entry inspects the exact page/reference/retained placement receipt before offering an explicit retry. A unique same-plan reference prevents a deliberate retry from duplicating the object.

After the reference is saved, the same object Save persists step edits through the existing review owner; page movement/title changes follow the page’s ordinary Save/autosave owner. The UI must distinguish unsaved checklist edits from a saved page—page Saved does not claim that unsaved step edits were committed. Global page Save does not silently discard them; navigation/reload retains their local copy under the same scope. No separate Save suggestion/Keep workflow is added. Removing a staged object leaves its generated source/review available in history and creates no dispatch.

## Placement receipt and recovery owner

Owner: shared surface/workPlans/workPlanPlacement.ts, invoked only by the typed Surface object host. This is a narrow browser receipt for an explicit author editor transaction, analogous to retained manual editor work; it never stores a second plan/execution state or claims APP proposal-review authority. Existing BuildProposalReview cannot be reused without a real generated-prose reservation and must not receive a fabricated one. No new APP schema/migration is required for this local placement receipt. Its availability and scope are explicit: unsaved placement recovery is within this browser; saved page reference/APP review survive browser loss.

The exact localStorage key is dmb:surface-work-plan-placement:v1 plus canonical World/document/conversation/source-turn/source-answer identity. The closed record contains schema=dmb_surface_work_plan_placement_v1; that identity; stable placement command_id; captured BuildProposalBasis (selection must be null); conversation pointer revision; canonical reference Markdown/digest; reviewed rows with stable existing Step IDs and expected review revision; optional acknowledged review revision; optional prepared transaction containing apply_id and exact before/after editor/draft digests; phase staged/review_saving/review_saved/applying/page_save_uncertain/saved/discarded; optional verified saved page revision/content digest; and retired_placements entries containing the previous command_id, captured basis, reference/digest, prepared transaction and explicit superseded_unresolved or superseded_unapplied disposition. Retired entries cannot recursively contain predecessor lists. Phase/field joins are validated. No source transcript, provider completion or success receipt is invented. Preserve corrupt/mismatched stored bytes and block writes until explicit recovery; never silently reset them.

Ordering is mandatory:
0. Acquire the same World/document Web Lock BEFORE initial creation/staging or any mutation of the shared receipt, including capture transfer, error/phase updates, predecessor retention and terminal cleanup. Under that lock, read/validate the existing key first and compare/adopt its command, revision/basis and phase. Never replace an existing applying/uncertain receipt with a staged copy. A new explicit placement atomically appends the old immutable predecessor before replacing the current fields. Corrupt bytes remain untouched. Release locks between operations; never hold one during model generation. Per-tab unsaved row notes may use the existing scoped draft storage, but cannot overwrite the shared receipt.
1. Retain and read back stable rows, IDs, reference and captured basis before any review PUT. If storage is unavailable, leave the object editable/read-only with Copy/recovery and block mutation.
2. Within that same document lock, re-read/compare the receipt, current reference absence and existing APP review. CAS saves exactly the retained rows. Persist its acknowledged revision before page preparation; an unknown review PUT is resolved by GET and exact row/identity comparison before another write. If different/newer, preserve both copies and stop.
3. Compute the host-created reference insertion with the existing canonical editor simulation; persist and read back phase=applying plus full exact before/after digests and apply_id BEFORE the real editor transaction. Only then mutate once. The existing editor local draft/protected-copy owner retains the full page; the placement receipt does not duplicate that whole-page source.
4. Use the existing page Save owner and exact saved-snapshot verification (saveBuildProposal’s owning invariants, without a fake generated proposal). A void promise is insufficient. Persist saved only after exact saved source/digest/revision confirmation. On any uncertain failure, retain applying/page_save_uncertain and do not clear the local receipt or source copies.

Reload/explicit retry first reads this receipt under the same document lock. Exact after-editor/draft state resumes checking/saving without insertion. Exact before state permits the same prepared transaction only on an explicit retry and only if the latest committed page/review/pointer still match; do not blindly reuse yesterday’s caret. A changed page opens the existing complete-copy reconciliation; afterward an explicit new placement preserves the earlier unresolved receipt. Retain superseded local receipts, same identity but distinct command_id, as an ordered immutable predecessor list within this record; the current before/after joins never overwrite an uncertain earlier attempt. The corresponding digest/state joins and distinct command IDs are part of validation. Missing Web Locks block placement with work retained.

A committed page containing the exact same plan identity prevents another insertion even when other page text changed. That proves an object already exists, not that an old exact whole-page Save completed; show the existing object and keep any unresolved earlier receipt inspectable. Different title/position/newer page edits are not overwritten. Duplicate references are a serialization refusal. Other tabs re-read durable review/CAS, local receipt and page state before mutation; localStorage events retire stale views. Storage failure after mutation cannot authorize a repeat; inspect the protected editor copy and committed page first. Removal/undo preserves APP plan/history; no mount/undo/reload executes a step.

Capture transfer belongs to the existing pending Build-request owner: persist the actual request capability basis under its real client identity before retiring the terminal request, then join the validated completed history turn by actual conversation/idempotency identity. A missing/failed transfer never invents an anchor or resends a completed generation. Preserve the typed plan in history and require explicit placement. Historical manual placement captures a new current basis. A plan object is insert-only; a captured replacement selection requires a deliberate new insertion position.
