## Additional findings from this live re-check (outside the 19-step table)

These don't map cleanly to one checklist row but were directly observed and matter for the next design pass:

1. **Frontmatter leak, reintroduced by the `GraphProjectionReader` consolidation.** The Gold Fixture lane renders the raw YAML frontmatter block (`--- title: "Session 1 - Stonebridge and Glowkindle Rats" document_class: play canon_layer: campaign … ---`) as literal visible text at the top of the prose pane. The old `GraphReviewProjectionLane` (deleted this session) had a `LEADING_FRONTMATTER_PATTERN` strip specifically for this; that stripping was never ported to `GraphProjectionReader`/its markdown pipeline, so consolidating both lanes onto the shared reader silently reintroduced the bug it had already been fixed once. Not confirmed whether the Live Run lane has the same leak (its scroll position defaulted mid-document in this session) — worth checking both lanes when this is fixed.
2. **Old tool tabs are still present and not cleaned up**, confirmed live in the toolbox: `Ingest Recap | Recap | Graph Preview | Graph Gold Review | Graph Review | Vocabulary Review | Party Registry | Statblock`. `Graph Preview`, `Graph Gold Review`, and `Vocabulary Review` are the three tools the new `Graph Review` workbench was supposed to eventually replace (Roadmap R11 / Design §8.11), and they're still live, unlabeled-as-deprecated destinations sitting right next to the new one. R11 has not been started, which is expected per sequencing, but the user experienced this directly as clutter/confusion in the toolbox, not as an abstract roadmap gap.
3. **Statblock / Encounter note buttons are permanent stubs, not "not yet, but wired."** `GraphReviewNodeGameCard.tsx` hardcodes `<button disabled>Statblock unavailable</button>` / `<button disabled>Encounter note unavailable</button>` — the §7.2 game-object enrichment adapter was never built. This is Design §8.1's headline promise ("If a statblock exists, I can open it") and it currently can never fire, even when a statblock genuinely exists for the node.
4. **Duplicate node-info surfaces compound the "too much metadata" complaint.** Clicking a pill opens an inline `GraphNodeExplorer` popover *and* leaves a second, fuller "node game card" available far below the fold — two different-shaped presentations of overlapping data, neither of which is the single obvious place to look.

## Session verdict for hand-off

The gold-vs-live two-lane prose comparison (Design §8.2) is real and close — this is a genuine step forward from the pre-dogfood state and fixed the "breadcrumbing" rendering-contract bug from the prior session. But the tool is not yet at the "magical" bar the design set for itself: metadata is still in the way, the node-inspection path requires scrolling past a full two-lane prose view to reach the actual card, that card duplicates an inline popover, and the surrounding toolbox still presents four competing graph-review destinations instead of one. The user was not able to complete the full author-draft-to-commit loop in this session. Recommend the next work pass prioritize, in order: (a) fix the frontmatter regression (small, clear regression from this session's own refactor), (b) collapse the inline-popover/game-card duplication into one place, (c) pull the "Stage node/relationship" actions and existing-object resolver up near the point of selection instead of after a long scroll, before attempting any further roadmap milestones (R4 enrichment adapter, R8/R9 LLM assist).
