## Outcome and invariant critique

From Play chat, the GM chooses Propose scene edit, asks Buddy to change the current existing scene, reviews Before/After, and applies it to this session copy. Existing content controller journals/autosaves via edition CAS; Plan, progress and notes remain intact. Media, tables and callouts remain supported by the shared Markdown editor.

An inert proposal has no write authority. Bind World, Run, original pin, exact saved edition/hash, Run revision/current Scene and saved note receipt before inference. Browser-only drafts block capture. Server never accepts a client full-document rewrite as proposal input. A generated candidate may replace only the current Scene body (including its child Choices/Options); preserve exact bytes outside this range and the sealed structure/frontmatter. Invalid output never becomes applicable. New media identities may only reference saved assets already present in admitted session context; existing identities can be repositioned/removed or presentation changed as requested. No external image URLs or new generation in this slice.

Read/inference cannot silently become graph publication, Plan write or session write. Apply requires explicit approval and fresh mounted capture: same World/Run/scene, Run revision, accepted edition/hash, no note/content draft, and unchanged full draft. Changed notes/progress invalidate review too. Existing CAS is the final persisted edition boundary; uncertain saves use the existing exact-command journal.

Durable proposal reservation freezes the admitted request basis and prevents repeat provider dispatch for the same proposal ID. Ready proposals survive reopen, are scoped by World+Run, and may be reviewed historically; changed basis disables Apply. Failed or interrupted generation does not auto-regenerate. A new explicit request uses a new ID. This is not a second content store: proposals reference existing immutable editions and persist only inert review evidence/candidate.
