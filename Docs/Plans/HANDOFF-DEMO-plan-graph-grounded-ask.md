## One user-visible capability

In the existing server-owned conversation for a saved Plan in a verified managed World, a user can ask a natural-language question that uses the exact committed Plan Markdown and, when authorized by an explicit versioned context policy, relevant evidence from that same World's active Graph. The answer and its validated evidence are visible in that same conversation and survive normal history reload and exact durable replay.

The current Plan Ask already resolves committed Markdown and may include a typed, revision-pinned playable-card focus from #911. It never uses mounted dirty editor bytes. This slice adds trustworthy Graph evidence to that current Ask; it does not create a second conversation or change existing graphless requests.

The answer remains useful co-GM prose grounded in admitted World Graph claims. Compact citation details identify the cited assertion/relationship, evidence-reference IDs, pinned revision, and that underlying source text was not opened; do not dump raw IDs or receipt fields into the prose. Source opening, source excerpts, source-anchor reads, and source-document claims are outside v1; reference metadata alone never supports a quotation or a claim about what a source document says. V1 does not complete passage- or quotation-backed planning; the existing product-local source opener remains a named follow-on for those claims.

This is read-only Ask. It does not write Graph data, edit Plan content, create proposals, change Compose/Revise, or close J1–J6/operator acceptance.

## Accepted product invariants

1. **Explicit context intent.** The opt-in consumer request adds only the accepted `plan_context_policy` object to `dmb_agent_turn_request_v1`; it sends no native World ID, binding version, Graph revision, or caller-selected scope. Keep `graph_request.mode = none` and `graph_selection = null`; never infer automatic context from `none`, route, or Graph existence. Policy-absent requests retain their current v1 bytes. Do not invent another wire version.
2. **Exact Plan basis.** Resolve World, Plan document, object revision, WorkRevision ID and number, and content SHA-256 from server authority. Keep the selected typed playable-card target bound to the same committed Plan basis. Never send or substitute the mounted dirty draft. When the editor is dirty, Ask uses the committed basis and visibly discloses that unsaved edits are excluded.
3. **Graph authority and scope.** Run the existing #835 loopback operator-bearer authorization before Graph, Plan-context, or provider work; it is not named-user or remote authorization. Derive the managed World only from the verified saved Plan. Resolve its active #836 native Graph binding server-side; never accept native World IDs, binding versions, GM authority, source roots, or revision pins from the client/model. The existing `project_managed_world_graph` read fence resolves the native ID and then rejects binding/native-ID/source-root drift. MIND confirms its existing R.3 read contract supports a fixed `scope_mode=WORLD`, `campaign_id=null`, authorized admissibility, and an exact revision pin. Use R.3's admitted objects, relationships, assertions, and stable `evidence_ref_ids`; revalidate evidence against the admitted projection and require world, scope, admissibility, and revision to agree across reads. Honor its bounded-result truncation/coverage signals. Recheck managed-to-native binding stability before accepting evidence. Do not invent a campaign selector, per-campaign query, or new MIND endpoint. Provide the model only selected claim-bearing assertions/relationships and validated evidence-reference metadata, not a full Graph dump.
4. **Evidence and citations.** A grounded answer section or claim must map, through structured response fields or equivalently proven alignment, to a claim-bearing Graph assertion/relationship and its validated evidence-reference IDs at the same Graph revision. A bare entity/node ID or unvalidated fallback sentence grounding is not evidence for a factual claim. Present concise co-GM prose with compact citation details identifying World Graph evidence and truthful source-not-opened status; keep raw identities and revision details out of the prose itself. Source opening, excerpts, anchor reads, and document-quotation claims require a later authorized contract and are excluded from v1.
5. **Bounded context.** Preserve the existing complete committed Plan Markdown, eligible conversation history, and question; do not introduce Plan-section relevance slicing or a second Plan context assembler. Add a bounded Graph packet/result cap and one final assembled-provider-input budget check that includes the full Plan, optional typed card focus, Graph packet, history, instructions, and schema/tool overhead. An 8,000-character question limit alone is not a full-envelope budget; SERVER owns the fail-closed accounting seam. Record the policy/packet version or digest, included claim/relationship/evidence-reference identities, and retrieval limit/truncation status. Do not add per-Plan-section inclusion/omission accounting. If the assembled request cannot fit, fail visibly before provider dispatch rather than clipping Plan or Graph context. A binding, pin, read, evidence-validation, budget, or receipt-freeze failure is a visible pre-dispatch failure with no automatic Plan-only downgrade. After a valid receipt freezes, insufficient evidence may produce a Plan-only answer only when all Graph claim payload is omitted; sufficient Graph context with no Graph-claim segment must be described as available but uncited/unused in the structured answer, not as a Plan-only dispatch. A separate policy-absent Ask after hard failure requires an explicit user action and a new idempotency key.
6. **Immutable receipt, completion, execution projection, and replay.** APP-STATE accepts the persistence design for contract settlement. Freeze the versioned, citation-free `PlanWorldGraphContextReceiptV1` (`dmb_agent_plan_world_graph_context_receipt_v1`) before provider dispatch; it binds the exact Plan basis, policy, managed/native IDs, active binding version, exact Graph revision, retrieval facts, packet disposition, dispatched IDs/digest, whole-envelope digest, and `evidence_mode=metadata_only` / `source_opened=false`. Keep retrieval candidates distinct from dispatched content: `retrieval_packet_sha256` plus candidate IDs describe bounded admitted retrieval; `dispatched_packet_sha256` plus dispatched IDs describe only claim payload sent; `assembled_input_sha256` covers the exact full provider envelope. When insufficient evidence is omitted, the dispatched digest is null and dispatched-ID sets are empty. The receipt hash covers these pre-dispatch fields but excludes the answer, completion, citation map, and response-only replay flag.

   Completion is a separate nullable `agent.turn.completion` envelope, `PlanWorldGraphCompletionV1` (`dmb_plan_world_graph_completion_v1`), atomically stored with assistant text and the unchanged receipt. It binds `context_receipt_sha256` and carries `answer_basis`, `answer_context_status`, ordered typed `answer_segments`, and `citation_map`. Segment types are `graph_claim`, `plan_claim`, `proposal`, and `connective`. Citation entries map one-to-one to Graph-claim segments and may reference only the exact dispatched assertion/relationship/evidence IDs and pinned revision; retrieved-but-omitted IDs cannot be cited. Each evidence citation retains `source_opened=false`. Existing graphless/policy-absent turns retain null receipt/completion and their current history behavior. Durable response/history must preserve the typed receipt and completion alongside `assistant_text`; the current plain-text-only projection is insufficient.

   The four completion outcomes are distinct: `graph_grounded` requires sufficient, complete, untruncated evidence plus mapped Graph claims; `graph_grounded_partial` requires sufficient but incomplete/truncated coverage plus mapped claims and visible disclosure; `plan_only_insufficient_evidence` requires an insufficient receipt and an omitted Graph claim packet, with no Graph claims/map; `plan_only_graph_unused` means sufficient Graph context was available but the structured answer contains no Graph-claim segment. For the last case, say “Graph context available; no Graph claims cited/used in the structured answer”; do not call it a Plan-only dispatch or claim the model did not internally use Graph context. Both Plan-only completion outcomes use `answer_basis=committed_plan`, but that describes output attribution. Hard binding, pin, evidence-validation, budget, or receipt-freeze failures occur before a valid receipt and must not dispatch or silently downgrade; only these true pre-dispatch failures may use `PlanWorldGraphContextFailureV1` (`dmb_plan_world_graph_context_failure_v1`) with `provider_dispatched=false`. A provider/model error or timeout after dispatch was attempted is a distinct post-dispatch outcome: retain the frozen receipt and truthful dispatch/lifecycle status, never report it as “not dispatched,” and never automatically downgrade. Any separate policy-absent Plan-only Ask after a hard pre-dispatch failure needs an explicit user action and a new idempotency key.

   Policy-bearing responses and history use only the accepted v2 envelopes: response `dmb_agent_turn_response_v2` nests `plan_context` with the existing receipt, nullable CompletionV1, nullable safe execution projection, and delivery-replay disposition; history uses `dmb_agent_conversation_history_v2`, with the same `plan_context` nesting on policy turns and no `plan_context` field on legacy turns. Receipt and CompletionV1 schemas/digests do not change. The execution projection may contain only its schema, claimability, authorization state, and `automatic_redispatch: false`; never expose execution event/attempt IDs, digests, arguments, provider/tool bodies, or prompt content. Completed replay returns stored answer/receipt/completion/execution before current Plan, binding, Graph, or provider reads. Pending refresh/history keeps the latest sidecar and original pins. Same-key policy, Plan basis, card focus, or intent changes conflict. Persist no sidecar in browser-local history.

   CompletionV1 uses `citation_map: null` for Plan-only outcomes. When present it has exact shape `{schema: "dmb_graph_citation_map_v1", context_receipt_sha256, entries: [{claim_id, target_kind, target_id, graph_revision, evidence_ref_ids, source_opened: false}]}`. Validate its receipt binding, exact one-to-one correspondence with graph-claim segments, target and revision agreement, non-empty evidence refs, and source-not-opened value. The execution-aware backend owns final producing-envelope evidence membership. Present concise target/revision/source-not-opened details; prefer a human-readable target when supplied, otherwise label the evidence by kind. Never show receipt/event IDs or a raw ledger dump.
7. **Card focus plus Graph.** Preserve #911's optional typed playable-card focus alongside `auto_plan_world` with independent fields. It remains pinned to the same Plan revision and separately fingerprinted; it does not change Graph scope. Do not overload `selected_object` or silently clear/relabel the target. The current rejection is an implementation guard to amend narrowly for this explicit policy, not a product restriction.
