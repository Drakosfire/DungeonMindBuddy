## Product and ownership

Buddy owns a read-only rules lookup service, user ToolHost UI and typed Agent broker tool. Both consumers use the same bounded evidence packet and citation identities. Results name ruleset/edition, source book/section, verified page identity, exact excerpt and immutable corpus revision; users can inspect the cited passage. Lookup is available independently of World graph retrieval. Retrieved rules are source evidence, not World facts, campaign canon, deterministic legality judgments or a new graph experiment. The existing Agent can reason over inspected passages but must separate quoted rules, interpretation, missing evidence and house rules. No extra answer-generation service is required.

RulesIngestion owns extraction and EvidenceUnits. DungeonMindServer RulesLawyer is design reference only (current origin/main 223cbbe92f64bb14019a1678cac1f4e2336efd40); do not import its Mongo model, BGE model initialization or direct provider calls into Buddy. ## Source handoff and bounded reads

Use a versioned, server-configured immutable rules-evidence bundle exported from existing Stage B outputs. It is a durable artifact contract between RulesIngestion and Buddy, not a runtime import of another repo or DungeonOverMind configuration. A manifest pins corpus revision/digest, ruleset/edition and source metadata; records retain unit ID, exact text/hash, structural path, page index/fingerprint, gate result and stable source citation. Do not infer printed page numbers from PDF indices. Missing printed labels must be labeled PDF page explicitly. Exclude failed extraction gates; report corpus gaps rather than certifying full coverage. PHB local inventory has 386 page outputs / 6,984 units, including 22 failed-gate pages; inventory alone is not a verified publication. Existing private artifacts remain private and are not checked into the product source. A reviewed export/import gate verifies identities, size bounds and evidence joins before runtime adoption. The public corrected occupancy unit can be an initial witness; it cannot masquerade as broad rule coverage.

Server imports only a configured artifact path and expected digest, never model/browser-selected paths or arbitrary books. Bound corpus bytes/unit counts/unit size and validate uniqueness/hash/source joins before admission. Use a compact server-side lexical index initially; no embedding model, GPU or whole corpus download in the browser. Results bound hits and aggregate excerpt bytes, preserve partial/empty/unavailable/error states and stable order. Deduplicate repeated exact lookup requests within a turn by corpus revision + ruleset + normalized query + limit; never conflate editions, suppress explicit retry of failures or carry successful cached results across changed corpus/access scope. Historical citations pin immutable passage identity and must remain inspectable after a newer corpus is selected, without claiming that historical text is current.

## Agent contract

Add an explicitly admitted read-only `lookup_rules` tool with question and configured ruleset selector only; no caller paths, graph revisions, source authority or provider options. Parent selects the allowed corpus and records tool authorization, packet/result digest and actual provider exposure. Bounds and cancellation follow current turn ownership. Duplicate equivalent calls reuse a successful same-turn packet and do not append duplicate passage context; failures remain explicit and retryable. The final response's rules citation IDs must be validated against actually exposed packet evidence, persisted with the turn and rendered as inspectable source links. Rules citations never pass through World assertion-ID validation as if they were graph claims.

The current Hermes policy has only graph and conversation_only modes and rejects tools in conversation_only. Design and review a minimal explicit rules capability for graph-disabled turns; do not append a hidden tool after whitelist validation, fake graph authority or weaken conversation_only. Existing graph-enabled turns may receive both independently authorized capabilities. Every model-visible tool must match the capability policy and parent broker. Cross-World/revoked-access/late-turn results must not expose prior private rules evidence.
