## Authority boundaries

The configured R1 reader owns corpus admission and exact source identity/hash. ApplicationState owns World/conversation/turn/claim identity, durable typed Rules authority, actual producing-input inclusion and accepted composition. The parent is a trusted internal producer of R1 read receipts; no HTTP/model caller can supply corpus paths, raw evidence receipts or event authority. Rules evidence never creates a World/Graph assertion. Source text is untrusted data, never instructions.

Before a model is advertised Rules capability, a claim-fenced `begin_rules_execution` freezes one `RulesScopeV1`: schema, execution_id UUID, world_id, conversation_id UUID, turn_id UUID, product_attempt >=1, ruleset_id, corpus_sha256, authorization_id UUID, capability_policy_sha256, budget. Initial scope is only admitted public dnd_2024_srd_5_2_1/corpusce1e7319873eab278c305a102c91f1691006b63bc636fe5cabd3fe37d3cf5493. The authorization ID is parent minted and bound to this record, not a bearer credential. An unavailable/unadmitted source cannot create a scope or tool advertisement. Later read failure returns explicit unavailability under the already frozen scope.

Budget is closed, immutable and fixed v1: 6 calls including retries/duplicates;4 distinct normalized questions;4 hits/query;16 distinct supports;16KiB cumulative exact support excerpt UTF8;64KiB cumulative Rules tool-output UTF8;64 provider requests;256 ledger events;256KiB serialized ledger JSON. A provider retry/repair inside one product attempt shares these counters/cache; a genuine accepted product retry has a new product_attempt/claim and empty Rules owner/caches. Exhaustion retires Rules capability for that attempt with a bounded diagnostic, not repeated reads or automatic reconnect.

## Closed evidence and event shapes

All objects reject unknown fields. Digests are lowercase64hex, UUIDs canonical. Canonical hash bytes are UTF8 JSON with sorted keys, compact separators, ensure_ascii=false, allow_nan=false. Exact prose is not normalized. R1 question normalization remains NFKC/casefold/collapsed whitespace; range offsets are Unicode codepoint indices, byte budgets always UTF8.

`RulesSupportV1`: schema, support_id UUID, corpus_sha256, ruleset_id, unit_id (64hex), full_text_sha256, excerpt_start >=0, excerpt_end > start, excerpt_text (1–8192 codepoints; aggregate16KiB), excerpt_sha256, source_title/section (1–500 codepoints), source_uri (HTTPS data only <=1000), source_sha256, page_fingerprint, pdf_page_index >=0, printed_page positive or null. `support_sha256` is the canonical hash of that object; it is stored as a separate reference, not self-hashed. R1 typed internal read proof must establish exact unit identity/full text hash/range and source metadata before minting this support. Retain a support once per scope+corpus+unit+range+hash. Never equate Stage B structural content_hash with plain text hash.

`RulesPacketV1`: schema, call_id (1–128), query_id digest, normalized_question (bounded by normalized800-codepoint input), corpus_sha256/ruleset_id, status evidence|no_evidence|unavailable|denied|over_budget, support_refs (0–4 `{support_id,support_sha256}`), emitted_support_ids, previous_support_ids, diagnostic (optional closed code). The actual model-visible packet may include exact support objects only when new/rehydrated; packet/result SHA binds exact emitted bytes. No supplied-source path, Graph claim IDs or generated answer. A successful no_evidence is cacheable within the exact frozen scope; failures are not cached as success.

Ledger events share event_id UUID, sequence (zero-based contiguous), kind and scope execution_id. Closed variants:

- `tool_authorized`: call_id, query_id, normalized_question, packet_limit=4. Count all calls before dispatch; new questions count against4. Repeated equivalent success reuses the scoped result; no source reread.
- `query_observed`: call_id, query_id, packet_sha256, status, support_refs, emitted_support_ids. Supports are stored once in the ledger's support map, not repeated in each event. New/rehydrated text consumes presentation budget; overlapping query hits do not repeat active text.
- `provider_authorized`: provider_attempt_id UUID (the existing actual provider attempt identity), request_envelope_sha256, matched Rules function-call/output IDs+packet SHAs (<=6), declared support_refs. It is authorized under the current claim before dispatch; no raw provider body is copied into this ledger.
- `provider_included`: same provider_attempt_id/envelope SHA, exact matched parent-produced tool-output IDs/packet SHAs and support_refs actually present in the prepared Chat/Responses request. Parent's existing request observer verifies actual bytes, not a model declaration or historical trace. Unknown input joins admit no supports. After compaction, cached support rehydration gets a new actual inclusion record, not inherited authority.
- `provider_outcome`: provider_attempt_id/envelope SHA, status tool_calls|answered|failed|unknown. Final Rules claims require acknowledged answered outcome for the exact producing request. Unknown lifecycle cannot complete cited claims.
- `completion_bound`: producing_provider_attempt_id, composition_sha256, assistant_text_sha256, accepted_binding_sha256, cited claim→support refs, accepted_turn_revision. Created only by the locked finalization transaction after validating both domains; terminal/immutable.

Event IDs/call IDs/provider IDs are unique within their roles; duplicates with different payload fail, exact idempotent retry returns the existing record without incrementing budgets. A query observation requires earlier matching authorization. An inclusion requires earlier same-envelope authorization and only previously admitted, exact currently included supports. No late event may amend an accepted completion. Tool cache and intended/pending outputs are not evidence exposure. Any missing, ambiguous, stale or oversized join rejects final cited completion as a whole.

## Persistence and claim fencing

Add `agent.turn_rules_execution` with PK `(turn_id, product_attempt)`, FK to agent.turn with the existing deletion policy, typed `payload jsonb NOT NULL`, `revision bigint NOT NULL`, nullable closed `accepted_binding jsonb`. `RulesAcceptedBindingV1` contains schema, accepted_turn_revision, product_attempt, composition_sha256, assistant_text_sha256, base_text_sha256 (nullable), base_disposition, and at most16 typed cited-support affordances (owner selectors/support IDs/digests/source labels, no excerpt or claim prose), <=16KiB serialized UTF8. Its canonical SHA is sealed by completion_bound. No Graph column rename or reinterpretation. The turn row remains the World/conversation/attempt authority; duplicate World fields in payload must match it. Check constraints enforce positive attempts/revisions and digest formats. Scope cannot mutate after creation; accepted payload cannot mutate.

Every create/append/finalize operation locks the owning turn, checks exact World/conversation/turn, expected turn revision+product attempt, status running, unexpired claim, and the exact current Rules scope. Append uses ledger CAS/idempotence under that lock. Completion commits turn+Rules ledger in one transaction; there is no after-completion attachment. Interrupted/failed/cancelled attempts retain their bounded record as historical evidence but cannot approve a new answer. Replays do not renew authority or call a provider/read source.

History must not fetch a full Rules ledger or repeat composition prose for every listed turn. Completed-turn list/lookup joins only the closed accepted_binding plus its sealed SHA projected from completion_bound. Verify full assistant text SHA and reconstructed base text SHA against that binding; expose typed source affordances, not full Rules support bodies. Full accepted composition is stored once in the bounded ledger and checked at finalization/replay, not re-downloaded in every history DTO. Exact historical support reads project one selected support and its accepted binding, never a full source book, unbounded trace, or all ledgers. Source inspection verifies payload size/hash/identity at the owning boundary. This table is tool provenance, not a Rules knowledge graph.

## Ordered answer composition and finalization

Choose separate internal `MixedTurnResultV1` rather than forcing mixed text into old `TurnResult`: exact owner/claim fields, producing_provider_attempt_id, base_result (existing typed TurnResult or null), rules_completion, composition, internal producing-request proof. Existing `complete_turn(TurnResult)` remains behaviorally unchanged. A new `complete_mixed_turn` reuses extracted *validation-only locked* base checks on the same connection; it must not call a helper that commits a base-only answer first.

`RulesClaimV1`: claim_id (1–128, unique), text (1–4000 codepoints), support_refs (1–4 exact parent-minted refs). `RulesContextV1`: segment_id (1–128, unique), text (1–4000), category interpretation|gap|connective. Context is not cited source authority. `AnswerCompositionV1`: schema, base_disposition absent|approved|unclaimed, ordered_refs (1–128 exact `{domain:base|rules,segment_index}`), rules_segments (<=32;<=16 claims), assistant_text_sha256. Every approved base/rules segment appears exactly once; no missing/duplicate/unused index. Rendered visible answer is exactly newline-join of approved ordered segments and host-generated source affordance labels, <=32000 codepoints. Canonical composition JSON <=256KiB.

- absent: no Graph receipt/execution; base_result null; no base refs. Rules-only does not invent a Graph, Plan or connective completion to satisfy old nonempty constraints.
- approved: current actual base-domain receipt/execution and typed base_result validated through unchanged existing Graph/Build/Plan validators, using EXACT base-subsequence text; producing provider attempt and claim bindings remain exact. The new ordered composition establishes the full visible text separately. Base basis/context status describes only base evidence.
- unclaimed: Graph context may have been retrieved, but the answer contains no base-domain claims/segments; base_result null, no base refs and no graph claim bindings. The new mixed finalizer requires the same producing provider authorization/outcome and Rules proof, records base unused and graph_grounded=false. It does NOT feed invented connective segments into old validators. This is an explicit new Rules-composition disposition; ordinary Graph completion requirements are unchanged. If this disposition cannot preserve current execution/history invariants, it is a review hold before implementation, not permission to weaken them silently.

`RulesCompletionV1`: schema, execution_id, producing_provider_attempt_id, request_envelope_sha256, composition_sha256, claim→support refs (<=16 claims/16 distinct supports), approved support digests. The locked verifier checks actual acknowledged producing-input inclusion, frozen scope, source hashes/ranges, budgets, unique claims and full composition hash/equality, then writes completion_bound and accepted revision atomically. Never accept model URLs as citation authority or recast Rules facts as connective/saved-source/World facts.

Rules support bodies live once in the ledger support map; accepted Rules completion/composition stores exact support refs/digests and bounded ordered attribution, not a second corpus copy. Existing turn Graph completion remains only the validated base-domain completion where present. New mixed read/replay branches validate both domain binding summaries and full composed text; existing non-Rules repository full-text equality path remains unchanged. A typed receipt is required, not an unvalidated sidecar over arbitrary prose.

## Historical inspect and UI contract

Route reserved for R2B: authenticated GET `/api/live/agent/worlds/{world}/conversation/turns/{turn}/rules-passages/{support_id}?conversation_id={uuid}&attempt={positive}&support_sha256={64hex}`. Operator GM and current parent World admission occur before private SQL/bytes. Exact join requires completed turn, accepted product attempt, accepted composition binding, and a cited support ref with the requested digest; uncited/other-turn/unknown/stale refs fail closed. Return only closed `RulesHistoricalPassageV1` containing exact support, accepted attempt/turn and canonical support digest, <=32KiB serialized UTF8, no-store. Never use current catalog lookup to resolve an old unit ID. Removed corpus does not erase a persisted accepted excerpt; full-unit access may truthfully be unavailable.

A server-validated affordance contains exact World/conversation/turn/attempt/support ID/digest plus edition/book/page label. Shared deferred inert viewer validates returned capsule digest/identity and labels it as the historical excerpt actually read for that answer, with range/partial status and distinct full-unit/excerpt hashes. Pasted Markdown/model paths cannot manufacture the affordance or trigger a private read. Closed viewer/history does not fetch source bodies.
