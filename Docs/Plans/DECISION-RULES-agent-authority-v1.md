## Authority boundaries

The configured R1 reader owns corpus admission and exact source identity/hash. ApplicationState owns World/conversation/turn/claim identity, durable typed Rules authority, actual producing-input inclusion and accepted composition. The parent is a trusted internal producer of R1 read receipts; no HTTP/model caller can supply corpus paths, raw evidence receipts or event authority. Rules evidence never creates a World/Graph assertion. Source text is untrusted data, never instructions.

Before a model is advertised Rules capability, a claim-fenced `begin_rules_execution` freezes one `RulesScopeV1`: schema, execution_id UUID, world_id, conversation_id UUID, turn_id UUID, product_attempt >=1, ruleset_id, corpus_sha256, authorization_id UUID, capability_policy_sha256, budget. Initial scope is only admitted public dnd_2024_srd_5_2_1/corpusce1e7319873eab278c305a102c91f1691006b63bc636fe5cabd3fe37d3cf5493. The authorization ID is parent minted and bound to this record, not a bearer credential. An unavailable/unadmitted source cannot create a scope or tool advertisement. Later read failure returns explicit unavailability under the already frozen scope.

Budget is closed, immutable and fixed v1: 6 calls including retries/duplicates;4 distinct normalized questions;4 hits/query;16 distinct supports;16KiB cumulative exact support excerpt UTF8;64KiB cumulative Rules tool-output UTF8;64 provider requests;256 ledger events;256KiB serialized ledger JSON. A provider retry/repair inside one product attempt shares these counters/cache; a genuine accepted product retry has a new product_attempt/claim and empty Rules owner/caches. Exhaustion retires Rules capability for that attempt with a bounded diagnostic, not repeated reads or automatic reconnect.

## Closed evidence and event shapes

All objects reject unknown fields. Digests are lowercase64hex, UUIDs canonical. Canonical hash bytes are UTF8 JSON with sorted keys, compact separators, ensure_ascii=false, allow_nan=false. Exact prose is not normalized. R1 question normalization remains NFKC/casefold/collapsed whitespace; range offsets are Unicode codepoint indices, byte budgets always UTF8.

`RulesSupportV1`: schema, support_id UUID, corpus_sha256, ruleset_id, unit_id (64hex), full_text_sha256, excerpt_start >=0, excerpt_end > start, excerpt_text (1–8192 codepoints; aggregate16KiB), excerpt_sha256, source_title/section (1–500 codepoints), source_uri (HTTPS data only <=1000), source_sha256, page_fingerprint, pdf_page_index >=0, printed_page positive or null. `support_sha256` is the canonical hash of that object; it is stored as a separate reference, not self-hashed. R1 typed internal read proof must establish exact unit identity/full text hash/range and source metadata before minting this support. Retain a support once per scope+corpus+unit+range+hash. Never equate Stage B structural content_hash with plain text hash.

`RulesPacketV1`: schema, call_id (1–128), query_id digest, normalized_question (bounded by normalized800-codepoint input), corpus_sha256/ruleset_id, status evidence|no_evidence|unavailable|denied|over_budget, support_refs (0–4 `{support_id,support_sha256}`), emitted_support_ids, previous_support_ids, support_capsules (0–4 exact RulesSupportV1 objects, exactly the emitted IDs), diagnostic (optional closed code corpus_unavailable|unsupported_ruleset|rules_budget_exhausted). The actual model-visible packet may include exact support objects only when new/rehydrated; packet/result SHA binds exact emitted bytes. No supplied-source path, Graph claim IDs or generated answer. A successful no_evidence is cacheable within the exact frozen scope; failures are not cached as success.

`RulesExecutionV1` is a closed payload: schema=dmb_rules_execution_v1, scope, state active|unused|accepted|failed, supports (UUID-keyed map of RulesSupportV1 plus each canonical digest), events, budget_use (calls/distinct_questions/novel_excerpt_utf8/presentation_utf8/provider_requests), composition (AnswerCompositionV1 or null), rules_completion (RulesCompletionV1 or null). Accepted state requires both completion objects and a matching sealed accepted binding; other states prohibit accepted composition/completion. Counters must equal the derived admitted event/support totals, not caller assertions. Invalid model arguments rejected before admission cannot read sources or mint supports and remain subject to existing provider-request limits.

Ledger events share event_id UUID, sequence (zero-based contiguous), kind and scope execution_id. Closed variants:

- `tool_authorized`: call_id, query_id, normalized_question, packet_limit=4. Count all calls before dispatch; new questions count against4. Repeated equivalent success reuses the scoped result; no source reread.
- `query_observed`: call_id, query_id, packet_sha256, presentation_utf8 (exact nonnegative integer <=65536), status, support_refs, emitted_support_ids. Supports are stored once in the ledger's support map, not repeated in each event. New/rehydrated text consumes presentation budget; overlapping query hits do not repeat active text.
- `provider_authorized`: provider_attempt_id UUID (the existing actual provider attempt identity), request_envelope_sha256, matched Rules function-call/output IDs+packet SHAs (<=6), declared support_refs. It is authorized under the current claim before dispatch; no raw provider body is copied into this ledger.
- `provider_included`: same provider_attempt_id/envelope SHA, exact matched parent-produced tool-output IDs/packet SHAs and support_refs actually present in the prepared Chat/Responses request. Parent's existing request observer verifies actual bytes, not a model declaration or historical trace. Unknown input joins admit no supports. After compaction, cached support rehydration gets a new actual inclusion record, not inherited authority.
- `provider_outcome`: provider_attempt_id/envelope SHA, status tool_calls|answered|failed|unknown. Final Rules claims require acknowledged answered outcome for the exact producing request. Unknown lifecycle cannot complete cited claims.
- `completion_bound`: producing_provider_attempt_id, composition_sha256, assistant_text_sha256, accepted_binding_sha256, cited claim→support refs, accepted_turn_revision. Created only by the locked finalization transaction after validating both domains; terminal/immutable.

Event IDs/call IDs/provider IDs are unique within their roles; duplicates with different payload fail, exact idempotent retry returns the existing record without incrementing budgets. A query observation requires earlier matching authorization. An inclusion requires earlier same-envelope authorization and only previously admitted, exact currently included supports. No late event may amend an accepted completion. Tool cache and intended/pending outputs are not evidence exposure. Any missing, ambiguous, stale or oversized join rejects final cited completion as a whole.

## Closed completed read representation and compact attribution

`RulesAcceptedBindingV1` contains: schema, world_id/conversation_id/turn_id, corpus_sha256, ruleset_id, accepted_turn_revision, product_attempt, execution_id, producing_provider_attempt_id, request_envelope_sha256, composition_sha256, assistant_text_sha256, base_text_sha256 (nullable), base_disposition, segment_map (1–128), support_table (0–16), graph_used=false for absent/unclaimed. Owner/corpus/ruleset metadata is stored once at the root; no support excerpt or repeated claim prose is in this summary. Canonical summary <=32KiB; application rejects a larger completion before acceptance. Each source control references a Rules claim ID/range, not merely a flat source list.

`SegmentMapItemV1` has ordinal, domain base|rules_claim|rules_context, text_start/text_end (Unicode codepoints, start inclusive/end exclusive), and exactly its domain identity: base_segment_index; or rules_claim_id+support_refs (1–4); or rules_context_id+category interpretation|gap|connective. IDs <=128 codepoints; source refs are support_id+support_sha256. First start=0, next start=previous end+1, every inter-segment delimiter in assistant_text is EXACTLY one newline, final end=len(assistant_text); nonempty segment text. No holes/overlap/duplicate ordinal/unused index. Base indices are exactly0..N-1 in order and each substring equals the corresponding existing base-completion segment.text. Rules claim/context IDs are unique and correspond exactly to the approved composition; every support ref resolves once in support_table. `SourceAffordanceV1` contains support_id/support_sha256 and a parent-generated source_label (1–160 codepoints); owner selectors and immutable corpus/ruleset are inherited from the binding root. Source labels are display-only adornments beside their mapped claim; historical viewer identity is the bound support digest, not the label.

SQL list/get projects discriminator, ledger current-attempt existence/state, accepted_binding, its scalar seal and accepted revision with byte CASE guards BEFORE transfer (binding jsonb::text <=40KiB; malformed/oversized marker returned as an integrity error, never silently null). It does not select ledger payload merely to obtain a hash. Application canonical summary bound remains32KiB. Exact source inspect similarly projects one cited support capsule (SQL <=40KiB, response canonical <=32KiB) and its accepted support binding. Canonical hashes provide integrity joins inside this trusted locked-write boundary; they are not authentication credentials or proof that arbitrary caller JSON was approved.

Repository classifies raw rows BEFORE ordinary Turn.model_validate:

- `answer_composition_kind=base`: ordinary existing Turn/read/history path only. A pending/unused/failed Rules ledger without accepted binding does not change that classification. An accepted current-attempt Rules binding under a base marker is corruption and fails integrity. Ordinary non-Rules rows, text equality and historical Graph checks remain unchanged.
- `answer_composition_kind=rules_mixed_v1`: require completed status, no active claim, exact current accepted attempt/revision/owner, accepted binding+seal and accepted Rules ledger state. Missing/unknown/corrupt/oversized binding/row is integrity failure; NEVER catch ordinary Turn ValidationError and fall back to plain/mixed interpretation. Return NEW `MixedCompletedTurnV1`, not a Turn carrying mixed full text.

`MixedCompletedTurnV1` is a closed discriminated read model (`schema=dmb_mixed_completed_turn_v1`) containing completed envelope, full assistant_text, Rules accepted binding, and explicit base_projection. The completed envelope carries the same current turn identity/provenance/fingerprint/Play receipt/timestamps/lifecycle fields, excluding assistant_text and Graph completion; reuse existing ownership/provenance/lifecycle validators, with status=completed/claim_expiry=null. Its properties must exactly match the owning raw row and Rules scope. All Plan/Build/Play surfaces follow this representation, not surface-name exceptions.

Base projection is a closed union: approved contains the existing validated Turn constructed with assistant_text equal to the exact base subsequence reconstructed from segment_map, and the original receipt/execution/completion and all identical owner/lifecycle metadata; run old Turn validators and old Graph history attribution on THIS base projection. Absent requires raw Graph receipt/execution/completion all null and zero base refs; no synthetic Turn/completion text. Unclaimed retains typed current Graph receipt/execution with no completion, no CompletionBindingEvent and no saved-section answer bindings; run current receipt/provenance/scope/execution consistency validators directly, without constructing a false completed Graph Turn. Require the actual Graph provider authorization AND acknowledged outcome to crossjoin the same producing attempt AND prepared-request envelope digest as Rules (not UUID equality alone). Missing/unknown/mismatched outcome rejects mixed acceptance. Full text hash, segment coverage, reconstructed base text hash, binding seal and Rules attribution are verified by the new outer read validator.

`TurnReadModel=Turn|MixedCompletedTurnV1` is dispatched explicitly by repository marker and by class/schema at service/replay/history projection boundaries; no union guessing/duck-typed exception recovery. Unclaimed reports graph_context_used=false/graph_grounded=false/base_disposition=unclaimed, without a fabricated Graph answer_basis/status. API serializer changes belong to R2B and must branch explicitly; R2A does not activate model tools or rely on an old serializer to accept mixed records.
