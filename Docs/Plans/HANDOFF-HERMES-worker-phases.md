## Outcome and limits

The five-turn synthetic actual-host witness used `openai-api` / `gpt-6-luna`, worker PID 1514024, and four warm reuses. All five host answers passed the deterministic hard gates; each host turn made one model call and zero tool calls. The final, corrected raw artifact is [`host-phases-20261002T080751Z.json`](../../evals/hermes_tuning/artifacts/host-phases-20261002T080751Z.json). Cold host wall time was 10,244.7 ms, including 1,878 ms to acquire/read the worker; the observed model call was 4,551.3 ms and host residual 5,693.3 ms. Worker spans: bootstrap/logger+home 1,216 ms, cached factory lookup 1 ms, plugin discovery 460 ms, agent construction 390 ms, provider conversation 6,283 ms, and normalization/projection below 1 ms. Warm host turns ranged 5,022.4–8,220.5 ms with 1,170.1–1,998.8 ms residual. Warm provider-conversation time exceeded the separately observed model call by 440–1,194 ms. Provider conversation encloses model-call time; the durations overlap. Worker-phase sums were within 13–24 ms of `host_worker_result_wait`.

The phase names reflect actual boundaries: `_initialize_worker_logger_home()` imports and caches `run_agent` during cold bootstrap/logger+home setup; the later factory lookup is cached. This experiment does not isolate true cold `run_agent` import time. Normalization/projection rounded below 1 ms in all five samples. These are descriptive measurements from one run, not evidence of a production speedup. The run used only the checked-in synthetic scenario: no private corpus, private C2 packet, or live Graph service was used. It does not establish native Graph crawling quality or TTFT.
