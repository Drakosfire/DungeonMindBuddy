## One question

Does one explicit bounded-follow-up instruction improve traversal and evidence-bounded answers on multi-hop, ambiguous, and no-path Graph questions, compared with the current graph-only Hermes route?

Run six matched pairs using the same policy-resolved `openai-api` / GPT-6 Luna graph-only route, fresh turn/retrieval sessions, model, scope, seed/candidate context, question, and system policy. Control uses the existing question unchanged. Treatment appends one fixed instruction: “When the initial Graph result leaves a requested relationship unsupported or ambiguous, make up to two bounded follow-up Graph reads: use `object` on an accepted candidate only if needed to resolve its identity, then `neighborhood` with an accepted node target and depth 1 or 2. Stop when the path is supported; if the bounded reads leave no path or multiple candidates, state that clearly without inferring a connection.” Verify pairwise system-prompt equality and that this appended instruction is the only input difference.

The six case fixture distinguishes three supplied-candidate cases from three discovered-candidate cases. Supplied candidates may be named in the shared model context, but that context contains no relationship edge or path. Discovered candidates are revealed only by the fake's first `search`; the fake must reject neighborhood/object targets that were not supplied or returned as candidates earlier in that turn. Include: supplied-candidate two-hop path; discovered-candidate two-hop path; object-disambiguation followed by a supported path; same-label ambiguous candidates that must remain unresolved absent distinguishing evidence; supplied-candidate no-path; and discovered-candidate no-path. The user question may name requested endpoints but must not disclose the expected chain. Keep gold edges, expected operation conditions, and abstention keys out of model-visible question/context and tool descriptions.

## Stateful fake and evidence rules

Use Buddy's existing Graph-only Hermes route and replace its retrieval dispatcher only inside the harness process. Maintain isolated per-arm fake state: accepted candidates, permitted operations, returned data, and phase of each turn. Initial `search` returns candidates and `outcome: partial` with no relationships. `object` may return only the requested accepted node's synthetic identity attributes. Return fixture relationships only from an allowed `neighborhood` operation using accepted node target(s); expose only edges reached by that request and honor requested depth. Negative/ambiguous cases must not leak hidden edges through search, object, summaries, diagnostics, or tool descriptions. Validate every model-supplied request against the model-visible schema: `targets: [{"kind":"node","id":"..."}]` and `depth` (1 or 2). Do not use executor-internal `seedNodeIds` or `maxDepth` in the model-facing fake contract. Record operation, targets, depth, result outcome, returned node/edge IDs, and sequence; never dump raw prompt/context into worker logs.

Hard gates are evaluated per answer: turn status is `ok`; every asserted relationship edge is present in the fake results returned before that answer; no invented nodes/edges or unsupported direction; required target ambiguity remains explicit; no-path wording is scoped to the bounded lookup and does not claim global nonexistence; answer distinguishes unsupported endpoint/motive when applicable. A failed retrieval operation counts as traversal failure even if the turn status is `ok`. Preserve this distinction in the artifact. Report tool/model call counts and exact operation sequence per arm, wall and observed provider-call durations, token usage, estimated cost, gate outcomes, raw answers, and the safe synthetic evidence path. Non-streaming output leaves TTFT unknown.

## Acceptance and limits

Report paired case-level tool-path changes and grounded/abstention pass rates on all six cases. A treatment improvement requires fewer unsupported answers or improved valid traversal without a grounding/abstention regression; lower wall time alone is not a win. Six synthetic pairs are exploratory and cannot establish native Graph-crawl quality, general model behavior, or a production prompt change. The fake demonstrates operation choice against a deterministic state machine only; it does not prove native retrieval, executor/session admission, live Graph availability, provenance, or source authority. If fake state cannot faithfully model the existing tool/session boundary without production changes, stop and report that blocker before provider use.
