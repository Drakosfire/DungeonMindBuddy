# ONBOARD: seed guest source documents

Status: ACTIVE under the owner's Sizzek delivery, review, merge and deployment authority. Serial successor to the merged guest Build foundation. Branch `codex/onboard-guest-source-documents` is based on fetched `origin/main`; this lane owns the guest source-document seed, its focused tests and this handoff. The separate graph-ingestion review defect is outside this lane. No production runtime or database is leased by implementation.

Outcome: the ordinary Build document picker opens the released Sizzek source pages in every guest World. Guests edit their own copies; reset creates fresh copies of the same released baseline. Owner pages and the released baseline never change as a result of guest actions. The entire Sizzek World is authorized for the demo; this lane must not introduce per-record approval or filtering.

The current guest binding copies only the native graph; authored pages are in Buddy's content store. Bind a frozen document bundle to the exact released graph baseline. A changed owner page or a later release must not silently alter an existing guest session. Initialize all pages atomically and idempotently under the existing session lifecycle lock, preserving source Markdown, titles, and provenance. Fail closed on a missing, invalid or mismatched bundle; do not present an empty or mixed-version World as a successful seed. Existing guest Graph-only operation and signed-in documents must remain unchanged when the capability is disabled. The bundle and its release association must be durable and reviewable; do not use mutable owner document IDs as guest authority or model-visible metadata.

Verification: exercise normal guest bootstrap and Build inventory/snapshot at their actual request boundary with synthetic pages; include two guests, owner isolation, edited-page preservation on retry, reset, concurrent initialization, malformed or mismatched release, missing CSRF, and expired sessions. Use the existing single owned disposable App database serially. Review the cumulative diff and obtain Bugbot review. Record exact focused checks, inherited failures, and any separate release evidence. The source files, media, graph expansion, serving integration and deployed desktop/mobile workflow still require verification; this slice alone is not completion of the Sizzek goal.

Runtime contract: when `DMB_GUEST_DOCUMENT_BUNDLE` is unset, existing guest behavior remains unchanged. When configured, it points to a host-provided UTF-8 JSON release artifact; `DMB_GUEST_DOCUMENT_BUNDLE_SHA256` must be its lowercase SHA-256. The version 1 object contains `graph_space`, `graph_revision`, and `documents`, a list of objects with `title` and `markdown`. Each guest's saved graph snapshot must match the bundle before any pages are created. The bundle is not yet wired into production Compose or populated with Sizzek sources; those are required release steps, not implied by the implementation.
