## Outcome and owner

Every existing Open statblock trigger requests the same World-scoped session.
Only that provider mounts the existing SavedMechanicsRevisionEditor. Remove the
per-button SavedStatblockDialog owner rather than retaining an isolated fallback.
The mechanics editor, revision journal, local recovery, MediaImageWizard and
StatblockRenderer retain their current responsibilities. No copied mechanics,
new store, Graph write, source lookup, generation or Save on request/close.
Carry the triggering scene/Plan presentation through the existing context
providers. It is transient UI context, not Save authority. Dirty/pending same-target
work retains its original presentation until clean; no silent encounter retarget.

Same-target requests reveal the same mounted editor with its exact selected
version, image studio and pending operation. Removing/replacing a trigger cannot
destroy that session. A different target requires the current editor's own clean
switch reading; busy/unresolved/dirty mechanics, summary or portrait work blocks
switch and reveals the existing session with an explanation. Save/recovery/revert
must settle that reading. World changes unmount the old scope and refuse foreign
requests; late results cannot overwrite another target. Close hides, preserving
the owner. Same-World route changes close the modal without deleting its session.

The shared owner loads the editor chunk only on explicit first opening, using
existing deferred-component error/retry handling. No eager editor/image-studio
import in the app entry bundle. One optional editor callback reports its own
switch reason; it is not a competing admission or persistence authority. Reuse
that same reason for existing navigation/observation guards.
