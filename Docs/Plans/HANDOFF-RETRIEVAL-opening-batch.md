## Conditional catalogs and editing

Initial navigation must include the same applicable graph/source/Rules/saved-page
metadata that the ordinary first retrieval could offer. Work is not selected yet:
metadata availability and permission to execute reads are different owners.
Do not call plan_read_enabled true before an actual work choice. Conditional
catalog entries must state their actual work applicability, including saved pages
that are applicable to discuss but not clarify. Explicitly inactive votes are not
discarded active obligations. Do not restrict the optimization to empty catalogs
or benchmark-specific Worlds to avoid proving this contract.

The NEW combined codec's fallback is defined over applicable votes after its
actual work choice. The old codecs' fallback and exact SDK bytes stay unchanged.
For example clarify plus an include vote for a discuss-only saved page cannot
authorize that page or count it toward successful finish. Retain the raw include
as explicitly inactive; apply actual fallback if no applicable candidates remain.

Writing, different destination and connected-page review keep exact capture,
placement, reservation and existing read permissions. Retrieval/post-read votes
do not grant writes or activate a readonly finish in those branches. Host lexical
inspection now occurs even for a request ultimately classified as writing: record
that cost/scope honestly. A missing reference or invalid capture cannot be repaired
with a newer source or an invented work choice.
