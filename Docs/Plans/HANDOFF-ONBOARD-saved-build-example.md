## Outcome and limits

The owner may include one optional saved scene example in a guest release and
review its exact text, associated released excerpts and optional image before
approving the candidate digest. A guest sees the saved scene, may open its
associated release-local excerpts and sees an explicitly selected released
image inline. Clearly explain that this is a saved example and was not created
from the visitor's temporary additions. Never imply a live generation call,
claim the source excerpts prove every scene detail, or present imagined scene
content as established canon. This slice does not simulate editing or image
generation, claim multi-hop reasoning was verified, transfer additions, contact
a model, or change the existing private World.

Label the result “Owner-authored saved example” and its citations “Selected
references”; do not imply an actual Build document, generation, or play session.
The owner may author the example in the selection surface, including text
copied from an actual Build workflow; text is not represented as generated by
Buddy without evidence. Require two distinct already-selected excerpts for an
example, identified as related material rather than automatic factual proof.
The two selections must resolve to distinct source spans (document, revision,
start and end), not duplicated indexes or repeated copies of the same span;
preserve and display support versus context roles without implying that either
proves the authored scene. Selection changes require a new prepared copy.
Optionally select one already-selected image; server assigns the public asset ID
from the sanitized copy. Owner selection and review must show exactly which
excerpts and image will accompany the scene. Render text as text with preserved
paragraph breaks, without interpreting Markdown, HTML, embedded links or remote
images. Existing copies without an example remain usable.

Bound title, body and image description; reject empty or overlong values and
control and bidi-override characters, and avoid accepting embedded URLs or
paths under the existing release text policy. The body, title, cited local IDs,
image local ID and accessible image description are included in the canonical
immutable manifest and therefore the reviewed digest. Resolve request-side
references to newly allocated release-local IDs server-side; do not expose
private document, asset, Graph or account identifiers. Require exact reference
closure, reject duplicate, missing, unselected or foreign references and fail
closed on malformed optional data. Publication still rechecks every underlying
native evidence binding, owner generation, source status and copy digest.
The optional field has a closed versioned schema with bounded text and reference
cardinality; validate it at both storage and publication. Absence means no
example; a malformed present field must fail closed, never silently hide from
review while remaining public. Restore and revocation use
the existing immutable-copy controls. The owner must be shown precisely what
will be served before approval; no hidden auto-included example.

The Sizzek source ingestion, owner review and publication, actual Build/media
authoring, graph-assisted multi-hop evidence, guest personalization, Play/reset,
and user testing remain separate unfinished parts of the goal. This slice is a
release presentation foundation, not an assertion those requirements passed.
