# Retired dossier standing lifecycle

The file-discovered six-dossier standing lifecycle is removed by this change.
This historical handoff grants no activation, write, bootstrap or resource authority.
Current source admission, native review and querying use their existing Core/WK
owners without a party-registry or dossier-directory prerequisite. Existing stored
sources, people, assertions, receipts and frozen benchmark evidence are preserved.
Git history retains the original implementation and verification record.

## Separately selected character creation requirement

The operator wants an intentional, extensible player-character creation flow.
Character is the fictional person and needs a name; Player is a separate owner
node for the real person playing that character. The ordinary flow must explicitly
select or create the Player and link it to the Character, then allow additional
facts and edges. Keep one durable native person identity; do not require a full
statblock or infer a real-person owner from a character name.

The previously reviewed six C1 dossier-backed people remain stored data. They
contain no verified Player identities and do not establish acceptance of this
complete creation flow. Its relationship vocabulary, owner scope, authorization
and operator acceptance belong to a separately selected successor.
