# DungeonBuddy Plan / Play cards prototype

Run from repository root:

```sh
python3 -m http.server 5203 --bind 127.0.0.1 --directory prototypes/plan-play-cards
```

Open http://127.0.0.1:5203/. This is an isolated, operator-interactive prototype, not the production Plan/Play route. It makes no API, provider, database or native Graph calls. Existing Buddy on 5202/7866 is untouched.

## Try it

1. Session 29 → Something Is Still Moving. Move among Situation, Read aloud, Do now, GM only, Relevant and Missing reference. In Play expand the rescue choice, select simultaneous actions, record what happened, and move to Count the Living. Recorded source-linked follow-ups remain optional; no navigation is forbidden.
2. Ironveil House → The House → floor-grouped room map. Open Family Kitchen and its related Kitchen Table scene, or Lysandra's Old Room and its focused contents/discovery blocks. Expand the room interaction and record a local outcome. The map indexes nine described spaces, without inventing adjacency or residence.
3. In Plan edit one scene's local Markdown. Existing marker identities/attributes must remain. The editor can insert references from the eight verified identities and rejects unknown IDs. Switch to Play, interact, record a local outcome, return to Plan. Prep stays separate from the journal.
4. Toggle Cards / Document. The same draft Markdown supplies both views; current scene/block is retained. Files exports local prep and outcomes separately.
5. Use Outline and Play notes in the scene toolbar to collapse either sidebar. Play notes starts closed; both panel preferences persist on refresh. The scene title, current block and preparation status live in that toolbar, leaving the card for content. Play notes is the local journal of what happened during Play.
6. Create scene: six short guided steps. Required name/situation/read-aloud/immediate prompt, optional `Action | consequence` lines, references awaiting review. Generated choices include an unexpected action and allow simultaneous activities. Stable local IDs are software-generated and never Graph identities.

Local preparation, pending action selections, unfinished outcome notes, and recorded outcomes persist in this browser origin's localStorage under `dmb-plan-play-cards-v1`. They are prototype state; production content remains unchanged. Exports allow keeping local work. A clean browser profile starts from exact fixtures; do not clear storage containing operator work without their approval.

## Canonical content and provenance

`content.json` stores each source Markdown once and indexed marker metadata. It is reproducibly generated by `build_fixture.py` from the imported Session29 linked derivative and verbatim House document. Session29 has 19 scenes grouped into 10 Beats, with nine choices/52 options nested inside scenes: not 90 separate cards. House has seven marked scenes and nine described spaces. Global GM notes and House tone remain outside scene edit boundaries and available through Intent/source context / Document. The underlying source distinguishes established handles, prep/proposed details and unresolved facts. Source labels are preserved author claims, not newly verified admissions. Outcomes are labeled local and separate.

The 72 existing node links refer to eight independently verified native `eldyrwild` IDs, imported in #884. Clicking a pill inspects that supplied identity; it does not pretend to query the Graph. House is distinct from Warehouse. Unverified named people/threats remain plain references; no entities/statblocks are fabricated. Guided creation rejects raw marker injection and unverified `dmb-node` URLs. Rich scenes, choices, status distinctions and unexpected paths remain in full Markdown.

## Limits

Standalone static UI and small purpose-built Markdown renderer. It preserves the Markdown source and displays prose, headings, lists, quotations, links and tables; it is not a replacement for the production semantic editor. Scene editing uses Markdown rather than block-specific rich editing. Room focus is derived from source headings, not independently admitted room nodes. Node inspector is a supplied-reference view, not a live Graph lens. No LLM/Agent conversation, combat integration, shared-user synchronization or production apply is claimed. Local outcomes are rehearsal records, not played canon. Adoption into Buddy's owning routes still requires owner review and integration.

Choice checkboxes are available in both Plan and Play. Log player direction saves selected IDs, readable labels, scene and timestamp as a separate local outcome, exportable through Files → Export outcomes for future recap work. Existing activates/suppresses links flag future scenes in the outline without disabling navigation. Recorded order determines the latest explicit status; later activation restores relevance. This is a local prototype log, not an ingestion or Graph write.

Logged selections stay checked on return. Something else accepts an unexpected-action note; typing selects that option, and Log player direction includes it in the saved record. Decision log is the optional history view of that same recording flow, not a second recording destination.

The floating Notes button opens one resizable writing pad shared across all cards/documents. It saves on input in browser-local storage and exports Markdown independently. Every choice group supplies a Something else note field, using the existing source option when present or a local fallback when absent.

Use Complete in the scene toolbar to mark/unmark a scene. The outline shows a checkmark and crossed-out title. Completed scenes remain navigable; status persists per document/scene in browser storage.

Files → Back up full session downloads a versioned JSON snapshot containing all current browser state: document drafts, decisions, pending choices/notes, shared writing pad and completion marks. Keep a separate copy for recovery; this prototype does not yet offer a restore-file UI.

Each card has a Scene notes disclosure at the bottom. Notes autosave independently by document/scene with visible saving/saved/error receipts; full-session backups include them. The floating pad remains shared.
